> **Project**: dailyDevInsight

> **대상 문서**: `docs/01-plan/features/insight-detail.md`, `docs/02-design/features/insight-detail.md`, `docs/02-design/screens/insight-detail.md`
> **대상 코드**: `InsightDetailService`, `InsightDetailRestController`, `InsightPageController.insightDetail()`, `insight-detail.html`, `insight-detail.js`

## 검증 범위 선언 (Audit Discipline)

- **검증한 것**: 서비스/컨트롤러/템플릿/JS 코드 정독 기준 Plan FR, Design 세부 주장 대조 + **`codex exec -s read-only`를 통한 2차 독립 교차검증**
- **검증하지 않은 것**: `./gradlew test` 실행(환경 JDK 불일치), 브라우저 실동작

> **v0.1 정정 이력**: 최초 작성(v0.1) 시 "Match Rate 100%"로 판정했으나, Codex 교차검증에서 실제 불일치 3건과 문서 서술 오류 2건을 발견함. 본 버전(v0.2)은 그 결과를 반영해 전면 재작성함 — **경량 자체 검증만으로는 이런 오류를 못 잡았을 것이라는 점에서, Codex 교차검증의 실효성을 보여주는 사례**로 남긴다.

## 1. Plan(FR) 대비 구현 일치 여부

| ID | Requirement | 코드 근거 | 일치 여부 |
|----|-------------|-----------|-----------|
| FR-01 | 조회수 세션당 1회 증가 | 세션 키로 게이팅됨. 단, **Codex 검증으로 `type` 대소문자 미정규화로 인한 중복 증가 가능성 발견** | ⚠️ 부분 일치(의도한 동작은 구현되어 있으나 엣지케이스 결함 존재) |
| FR-02 | 좋아요/북마크 토글 + 실시간 카운트 | `toggleLike`/`toggleBookmark` 확인 | ✅ 일치 |
| FR-03 | 댓글 500자 제한 + 대댓글 등록 | 확인됨 | ✅ 일치 |
| FR-04 | 본인 댓글만 삭제, 소프트 삭제 | 확인됨. 단, **부모 삭제 시 자식이 승격 표시되는 부수효과는 Plan에 기술 없음** | ⚠️ 부분 일치(요구사항 자체는 충족하나 연쇄 동작이 문서화 안 됨) |
| FR-05 | 비로그인 시 401 | 확인됨 | ✅ 일치 |
| FR-06 | 다단 대댓글 허용 여부(정책 미결정) | **[v0.1 계산 오류 정정] 이 항목은 "구현 완료 요구사항"이 아니라 "정책 미결정 상태"이므로애초에 Match Rate 분모/분자 어느 쪽에도 넣지 않는 것이 맞음** | — (집계 제외) |

**FR 일치율(집계 대상 5개 중): 완전 일치 3 / 부분 일치 2 / 불일치 0 → 단순 “일치 개수”로 퍼센트화하는 것 자체가 부분 일치를 왜곡하므로 퍼센트 대신 항목별 상태로 표기**(§4 참조)

## 2. Design 문서 세부 주장 대조 (Codex 검증 후 최종)

| Design 문서 주장 | 코드 확인 결과 | 일치 여부 |
|---|---|---|
| SSR 초기 페인트 후 JS가 즉시 재조회 | 확인됨(단 "페이지 로드 완료" 대기가 아니라 스크립트 실행 즉시) | ⚠️ 부분 일치 → v0.3에서 정정 완료 |
| 좋아요/북마크는 카운트만 부분 갱신, 댓글은 전체 재렌더링 | 확인됨 | ✅ 일치 |
| 댓글 목록이 메모리 트리 조립(재귀 쿼리 아님) | 확인됨 | ✅ 일치 |
| 다단 대댓글이 서버·프론트 모두 미차단 | 확인됨 | ✅ 일치 |
| 캐시 무효화가 `allEntries=true` | 확인됨. 단 조회수 증가 시의 clear는 `@CacheEvict` 아니라 `CacheManager.clear()` 직접 호출(다른 4개 메서드와 무효화 메커니즘이 다름) — v0.3에서 정정 완료 | ⚠️ 부분 일치 → 정정 완료 |
| 댓글 escape가 4개 문자 처리 | **[오류] 실제로는 5개 문자(`&<>"'`)** — v0.1 Analysis가 이를 "실질적 불일치 아님"으로 넘어간 것 자체가 판단 오류였음 | ❌ 불일치 → v0.3에서 정정 완료 |
| SSR이 "대댓글 포함" 댓글 목록을 표시 | **[오류] SSR은 최상위 댓글만 렌더링, `comment.replies`는 서버 템플릿에서 전혀 출력 안 됨** | ❌ 불일치 → Screen 문서 v0.2에서 정정 완료 |

## 4. 종합 판정

**"Match Rate 100%"라는 v0.1의 판정을 철회한다.** 원인: (1) 정책 미결정 항목을 완료 항목으로 산입, (2) 실제 코드와 다른 서술(escape 문자 수, SSR 대댓글 표시 여부, "모든 상호작용 통일")을 교차검증 없이 "일치"로 판정.

Codex 검증 이후 재정리한 상태:

| 구분 | 완전 일치 | 부분 일치(문서 정정 완료) | 불일치(정정 완료) |
|---|---|---|---|
| Plan FR | 3 | 2 | 0 |
| Design 세부 주장 | 4 | 2 | 2 |
| Report 서술 | — | — | 1 |

모든 불일치·부분일치 항목은 본 사이클 내에서 Design/Screen 문서를 정정해 **현재 시점 기준으로는 문서-코드 재일치 상태**다. 다만 최초 판정 오류 자체를 숨기지 않고 기록으로 남긴다(Audit Discipline).

## 5. Known Gaps와의 구분

Design 문서 §8에 이미 기록된 항목(다단 대댓글 정책 미결정, SSR 대댓글 미표시, 조회수 세션키 대소문자 이슈, 부모삭제시 자식승격, depth/페이지네이션 부재, `getEngagementOnly` 네이밍, 캐시 무효화 범위, 좋아요/북마크 중복 구현, 이력 미보존, 서비스 유닛 테스트 부재)은 "불일치"가 아니라 후속 개선 과제다.

## 6. 미확인 리스크

- `./gradlew test` 미실행
- 브라우저 렌더링(다단 대댓글 시 UI, JS 비활성 환경) 미확인
- Codex가 제안한 확인 항목(대소문자 접근 시 조회수 실제 동작, 사용자 2명·콘텐츠 2건 기준 캐시 무효화 등)은 코드 정독으로 논리적 추론만 했고 실제 실행 검증은 안 함
